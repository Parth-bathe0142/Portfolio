Krypt is a workspace of three crates: a CLI client, a Spin server compiled to WebAssembly, and a shared crate holding validation logic and DTOs used by both sides.

Why Spin and WASM

Spin runs each incoming request in a new, sandboxed WASM instance with its own linear memory. Instances start in microseconds, so this instance-per-request model is practical. It is conceptually similar to CGI's process-per-request, but without the cost of spawning processes or the platform-specific binaries.

Security model

  • Stored keys are encrypted on the server with the user's password, and re-encrypted when the password changes.
  • Every request is authenticated. There are no sessions or tokens.
  • The password is stored locally in the system keyring.

Platform support

  • Keyring backends: Secret Service on Linux, Keychain on macOS, Credential Manager on Windows.
  • Clipboard: wl-copy for Wayland and arboard elsewhere. Krypt probes both on first use and remembers the one that works.
  • Copied keys can be cleared from the clipboard after a configurable timeout (1-60 seconds), or by pressing enter to clear immediately.

Limitations

  • No account recovery: losing the password means losing the data.
  • Uses an older spin_sdk (v3.1.0) for Fermyon Cloud compatibility, which only supports WASIp1. Will be updated once Akamai functions become available to the general public.
