SSR SPA with HTMX

Navigation links use hx-get to fetch a page and swap it into <main>, with hx-push-url keeping the address bar in sync. Each route checks whether the request came from HTMX and returns either just the fragment or the full page. The same routes therefore serve both in-app navigation and direct visits, refreshes and the browser's back button. Alpine handles small pieces of client-side state such as the accordions.

Architecture

The app is a Spin application made of four components plus a shared crate:

  • pages: renders every public page and fragment.
  • admin: the interface for adding content, such as uploading certificates and updating the resume. It's protected by a password, with a JWT stored in Axum's private cookie jar.
  • api: serves non-HTML data, such as the files and images uploaded through the admin pages.
  • shared: code common to the components.

Other static assets are served by Spin's asset server. Spin's SDK is pinned to v3.1.1 for Fermyon Cloud compatibility. To keep the app portable, each Spin handler just forwards the request into a regular Axum router and converts the response back. Spin only runs the components, while routing and logic stay in plain Axum.

Pages

  • Home: summary, education and skills.
  • Projects: the entries you're reading now.
  • Certificates: a paginated list driven by HTMX.
  • Resume: rendered in the page with a download button.

Why Spin

I already had a Fermyon account from Krypt, and hosting was free. Spin's per-request execution model suits a site like this less well than a long-running server, so if I move to a VPS the Axum app can come along mostly as it is.

Work in progress

  • Styling isn't finalised and the layout isn't responsive yet.
  • Editing the details of uploaded certificates is not implemented.
  • The resume needs an image fallback for devices that can't display PDFs in the browser.
